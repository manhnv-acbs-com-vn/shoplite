# 1.3 - Viết custom hook và kiểm thử

**Thời lượng:** 45 phút · **Kết quả:** 4 hook bắt buộc (+2 nâng cao) chạy thật trong Claude Code.

## Lý thuyết nhanh

**Hook** là lệnh do _bạn_ viết, được Claude Code tự động chạy tại các thời điểm cố định trong vòng
làm việc của agent. Khác với `CLAUDE.md` (lời khuyên), hook **luôn chạy** - phù hợp cho việc phải
đảm bảo 100%: chặn thao tác nguy hiểm, format code, chạy test, ghi log.

```text
Bạn gửi prompt ──► [UserPromptSubmit] ──► Agent suy nghĩ ──► muốn dùng tool
                                                               │
                                                     [PreToolUse]  ◄── có thể CHẶN
                                                               │
                                                      Tool chạy (Edit/Bash/...)
                                                               │
                                                     [PostToolUse] ◄── format, log, báo lỗi
                                                               │
                                       Agent định kết thúc ──► [Stop] ◄── có thể bắt làm tiếp
```

| Event                | Khi nào                        | Dùng để                                           |
| -------------------- | ------------------------------- | ---------------------------------------------------- |
| `SessionStart`     | Mở / resume phiên             | Nạp thêm ngữ cảnh (nhánh git, issue đang làm) |
| `UserPromptSubmit` | Trước khi prompt được gửi | Chặn prompt chứa secret, thêm ngữ cảnh          |
| `PreToolUse`       | Trước khi tool chạy          | Chặn / hỏi / cho phép thao tác                   |
| `PostToolUse`      | Sau khi tool chạy xong         | Format, lint, ghi log                                |
| `Notification`     | Agent cần bạn chú ý         | Thông báo desktop                                  |
| `Stop`             | Agent định trả lời xong     | Quality gate: test fail thì làm tiếp              |

(Claude Code có hơn 30 event; bảng trên là các event hay dùng nhất.)

**Giao tiếp với hook:**

- **Input:** JSON qua `stdin`, gồm `session_id`, `cwd`, `hook_event_name`, `tool_name`,
  `tool_input` (ví dụ `tool_input.command` với Bash, `tool_input.file_path` với Edit/Write)...
- **Exit code:** `0` = ổn; `2` = **chặn**, nội dung `stderr` được gửi cho agent làm lý do; mã khác
  (kể cả `1`) = lỗi không chặn, thao tác vẫn chạy.
- **JSON output (stdout, exit 0):** trả quyết định có cấu trúc, ví dụ
  `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "..."}}`.

**Khai báo** trong `.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "node",
            "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/log-bash.mjs"]
          }
        ]
      }
    ]
  }
}
```

- `matcher`: tên tool, nhiều tool nối bằng `|` (`"Edit|Write"`).
- Dạng `command` + `args` chạy trực tiếp không qua shell → **chạy giống nhau trên Windows/macOS/Linux**.
  `${CLAUDE_PROJECT_DIR}` là thư mục gốc dự án.
- Ta viết hook bằng **Node.js** (dự án đã cần Node) thay vì bash + `jq` để mọi hệ điều hành đều chạy được.

> ⚠️ Hook chạy với toàn quyền của user trên máy bạn. Chỉ dùng hook bạn đã đọc hiểu.

## Hook 1 - "Hello hook": ghi log lệnh Bash (PostToolUse) · 8'

Tạo `.claude/hooks/log-bash.mjs`:

```js
#!/usr/bin/env node
// PostToolUse (matcher: Bash) - ghi lại mọi lệnh Bash agent đã chạy
import { appendFileSync, mkdirSync } from "node:fs";
import path from "node:path";

const input = JSON.parse(await readStdin());
const projectDir = process.env.CLAUDE_PROJECT_DIR ?? input.cwd;
const logDir = path.join(projectDir, ".claude", "logs");

mkdirSync(logDir, { recursive: true });
appendFileSync(
  path.join(logDir, "bash-history.log"),
  `${new Date().toISOString()}\t${input.tool_input?.command}\n`,
);
// Ghi toàn bộ payload để xem Claude Code gửi gì cho hook
appendFileSync(path.join(logDir, "hook-payloads.jsonl"), JSON.stringify(input) + "\n");

async function readStdin() {
  let data = "";
  for await (const chunk of process.stdin) data += chunk;
  return data || "{}";
}
```

**Test bằng tay** (giả lập đúng cách Claude Code gọi hook):

```bash
# macOS / Linux / Git Bash
export CLAUDE_PROJECT_DIR="$PWD"
echo '{"tool_name":"Bash","tool_input":{"command":"npm run lint"}}' | node .claude/hooks/log-bash.mjs
cat .claude/logs/bash-history.log
```

```powershell
# Windows PowerShell
$env:CLAUDE_PROJECT_DIR = (Get-Location).Path
'{"tool_name":"Bash","tool_input":{"command":"npm run lint"}}' | node .claude/hooks/log-bash.mjs
Get-Content .claude/logs/bash-history.log
```

**Đăng ký** - thêm khóa `hooks` vào `.claude/settings.json` (cùng cấp với `permissions`):

```json
"hooks": {
  "PostToolUse": [
    {
      "matcher": "Bash",
      "hooks": [
        { "type": "command", "command": "node", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/log-bash.mjs"] }
      ]
    }
  ]
}
```

**Test trong Claude Code:** gõ `/hooks` để thấy hook đã được nạp (nếu chưa thấy, khởi động lại
`claude`). Gửi `Cho tôi xem git status và danh sách nhánh`. Sau đó mở
`.claude/logs/hook-payloads.jsonl` và trả lời: payload có những trường nào? `tool_response` chứa gì?

✅ **Checkpoint:** log có các lệnh agent vừa chạy.

## Hook 2 - Bảo vệ file nhạy cảm (PreToolUse + exit 2) · 8'

Tạo `.claude/hooks/protect-files.mjs`:

```js
#!/usr/bin/env node
// PreToolUse (matcher: Edit|Write) - chặn sửa file nhạy cảm bằng exit code 2
import path from "node:path";

const PROTECTED = [
  { pattern: /(^|\/)\.env(\..*)?$/, reason: "file biến môi trường có thể chứa bí mật" },
  { pattern: /(^|\/)package-lock\.json$/, reason: "chỉ được thay đổi qua lệnh npm install" },
  { pattern: /^storage\//, reason: "dữ liệu đơn hàng thật, không sửa bằng tay" },
  { pattern: /^\.git\//, reason: "không được sửa nội bộ git" },
];

const input = JSON.parse(await readStdin());
const filePath = input.tool_input?.file_path;
if (!filePath) process.exit(0);

const projectDir = process.env.CLAUDE_PROJECT_DIR ?? input.cwd;
const relativePath = path.relative(projectDir, filePath).split(path.sep).join("/");

for (const { pattern, reason } of PROTECTED) {
  if (pattern.test(relativePath)) {
    console.error(`⛔ Hook protect-files: không được sửa "${relativePath}" (${reason}).`);
    process.exit(2); // 2 = CHẶN, stderr được gửi cho agent
  }
}

async function readStdin() {
  let data = "";
  for await (const chunk of process.stdin) data += chunk;
  return data || "{}";
}
```

Test bằng tay - lần lượt mong đợi `exit=2` và `exit=0`:

```bash
echo "{\"tool_name\":\"Edit\",\"tool_input\":{\"file_path\":\"$PWD/package-lock.json\"}}" | node .claude/hooks/protect-files.mjs; echo "exit=$?"
echo "{\"tool_name\":\"Edit\",\"tool_input\":{\"file_path\":\"$PWD/src/lib/format.ts\"}}" | node .claude/hooks/protect-files.mjs; echo "exit=$?"
```

Đăng ký vào `PreToolUse` với `"matcher": "Edit|Write"`. Test trong Claude Code:

```text
Sửa trực tiếp file package-lock.json, đổi "version" thành "0.2.0"
```

Kết quả mong đợi: agent nhận thông báo `⛔ Hook protect-files...` và dừng / đề xuất cách khác.

> 💡 Vì sao không thử với `.env.local`? Rule `deny Read(./.env.*)` ở bài 1.2 đã chặn trước khi tới
> hook. Đây là **phòng thủ nhiều lớp**: permission rule + hook cùng bảo vệ file bí mật.

## Hook 5 (nâng cao) - Quality gate khi agent kết thúc (Stop) · 8'

```bash
cp ../lab-guides/module-1-ai-coding-agent/reference/.claude/hooks/quality-gate.mjs .claude/hooks/
```

Logic: nếu `git status` cho thấy `src/` có thay đổi → chạy `npm test`. Test fail → trả
`{"decision": "block", "reason": "..."}` để agent **không được dừng** mà phải sửa tiếp.
Trường `stop_hook_active` giúp tránh vòng lặp vô hạn.

Đăng ký (Stop không có matcher):

```json
"Stop": [
  { "hooks": [ { "type": "command", "command": "node", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/quality-gate.mjs"], "timeout": 120 } ] }
]
```

Test:

```text
Đổi ngưỡng miễn phí giao hàng thành 400.000đ. Chỉ sửa hằng số, không cần chạy test.
```

Quan sát: khi agent định kết thúc, hook chạy test → 2 test fail → agent bị buộc phải xử lý (cập nhật
test hoặc hỏi lại bạn). Nhấn `Ctrl+O` để xem transcript chi tiết. Cuối bài hoàn tác:
`git checkout -- src/`.

## Debug hook

| Cách                                       | Khi nào dùng                                       |
| ------------------------------------------- | ---------------------------------------------------- |
| Pipe JSON giả vào script, xem `echo $?` | Luôn làm trước khi đăng ký                    |
| `/hooks`                                  | Xem hook nào đã được nạp, từ file nào       |
| `Ctrl+O` (transcript)                     | Xem hook chặn / lỗi trong phiên                   |
| `claude --debug-file ./claude-debug.log`  | Xem chi tiết hook nào chạy, exit code, thời gian |

Lỗi thường gặp:

- ⚠️ Dùng `exit 1` để chặn → **không chặn**. Phải dùng `exit 2` (hoặc JSON `permissionDecision: "deny"`).
- ⚠️ Đặt `permissionDecision` ở cấp ngoài cùng của JSON → bị bỏ qua; phải nằm trong `hookSpecificOutput`.
- ⚠️ Script in thêm chữ ra stdout trước JSON → JSON không parse được.
- ⚠️ Hook không chạy → JSON settings sai cú pháp, chưa _Trust this folder_, hoặc cần khởi động lại `claude`.
- ⚠️ Viết `$CLAUDE_PROJECT_DIR` trong chuỗi `command` dạng shell → không chạy trên PowerShell. Dùng dạng
  `"command": "node", "args": ["${CLAUDE_PROJECT_DIR}/..."]` như trên.
