# 2.3 - Lập kế hoạch kỹ thuật với `/speckit-plan`

**Thời lượng:** 25 phút · **Kết quả:** `plan.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md`.

Spec trả lời _cái gì_. Plan trả lời _làm thế nào_ với stack cụ thể - và phải qua **Constitution Check**.

## Bước 1 - Chạy `/speckit-plan` (10')

Bạn cung cấp định hướng kỹ thuật; agent đọc spec, constitution và codebase để lập kế hoạch chi tiết.

**Prompt**

```text
/speckit-plan Dùng đúng stack hiện tại của ShopLite: Next.js 16 App Router, TypeScript strict, Zod 4,
Tailwind v4, Vitest + Testing Library, Playwright. Không thêm dependency, không thêm database.
- Danh sách mã giảm giá là dữ liệu tĩnh trong src/data/ (giống products.ts).
- Logic thuần (tra mã, kiểm tra điều kiện, tính tiền giảm) đặt trong một feature mới src/features/coupons/,
  tích hợp vào quy tắc tính tiền hiện có ở src/features/checkout/pricing.ts.
- Client cần kiểm tra mã trước khi đặt hàng để hiển thị ngay số tiền giảm.
- POST /api/orders nhận thêm mã giảm giá; server tự kiểm tra và tính lại, không tin số liệu từ client.
- Order lưu mã đã dùng và số tiền giảm; trang chi tiết đơn hàng hiển thị dòng giảm giá.
- Đơn hàng cũ trong storage/orders.json (không có trường giảm giá) vẫn phải hiển thị đúng.
Đọc AGENTS.md để biết codemap và quy ước.
```

Agent thực hiện theo 2 pha:

| Pha     | Output          | Nội dung                                                             |
| ------- | --------------- | -------------------------------------------------------------------- |
| Setup   | `plan.md`       | Technical Context, **Constitution Check**, cấu trúc thư mục dự kiến  |
| Phase 0 | `research.md`   | Các quyết định kỹ thuật: Decision / Rationale / Alternatives         |
| Phase 1 | `data-model.md` | Thực thể (Coupon, AppliedCoupon, Order mở rộng...), quy tắc validate |
| Phase 1 | `contracts/`    | Hợp đồng API (request/response, mã lỗi)                              |
| Phase 1 | `quickstart.md` | Kịch bản kiểm tra thủ công từng user story                           |

## Bước 2 - Review plan (10')

Tự kiểm tra (đây là bước quan trọng nhất - sửa plan rẻ hơn sửa code rất nhiều):

- [ ] **Constitution Check** pass hết; nếu có vi phạm thì có giải thích trong _Complexity Tracking_.
- [ ] Danh sách file tạo mới/sửa khớp codemap (không tạo `src/services/`, `src/utils/` lạ).
- [ ] `contracts/` định nghĩa rõ mã lỗi (mã không tồn tại, hết hạn, chưa đạt tối thiểu) và format
      lỗi `{ error: { code, message, details } }` hiện có.
- [ ] `data-model.md` xử lý **đơn hàng cũ** không có trường giảm giá (tương thích ngược).
- [ ] Logic tính tiền vẫn nằm ở một chỗ dùng chung cho client và server (không viết 2 lần).
- [ ] `quickstart.md` có kịch bản thử với cả 3 mã ví dụ.

Không hài lòng? Yêu cầu agent sửa trực tiếp, ví dụ:

```text
Trong plan.md, đổi thiết kế: không tạo endpoint riêng /api/coupons/validate nữa mà [ý của bạn]...
Cập nhật lại research.md và contracts/ cho nhất quán.
```

## Bước 3 (tùy chọn) - `/speckit-checklist` (5')

Checklist trong Spec Kit là **"unit test cho requirement"**: kiểm tra spec/plan có viết đủ, rõ,
nhất quán không - không phải kiểm tra code.

```text
/speckit-checklist security - tập trung vào khả năng gian lận giảm giá và validate input
```

Kết quả: `specs/001-.../checklists/security.md`. Đọc từng mục, tick những mục đã đạt; mục chưa đạt
→ quay lại sửa spec/plan.

## Bước 4 - Commit

```bash
git add specs
git commit -m "docs(plan): coupon code implementation plan"
```

(và `contracts/`); Constitution Check không có vi phạm chưa giải thích.
