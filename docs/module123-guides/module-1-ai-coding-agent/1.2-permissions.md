# 1.2 - Cấu hình permission cho AI Coding Agent

**Thời lượng:** 30 phút · **Kết quả:** `.claude/settings.json` với rule allow / ask / deny đã được kiểm thử.

## Lý thuyết nhanh

### Permission mode - "mức tự chủ" của agent

| Mode                | Hành vi                                                  | Bật bằng                           |
| ------------------- | -------------------------------------------------------- | ---------------------------------- |
| `default` (Manual)  | Hỏi trước khi dùng tool lần đầu (sửa file, chạy lệnh...) | `Shift+Tab` / settings             |
| `acceptEdits`       | Tự sửa file trong dự án, vẫn hỏi khi chạy lệnh           | `Shift+Tab`                        |
| `plan`              | Chỉ đọc và lập kế hoạch, **không sửa** gì                | `Shift+Tab`                        |
| `auto`              | Một bộ phân loại tự duyệt thay bạn                       | `Shift+Tab` (nếu tài khoản hỗ trợ) |
| `dontAsk`           | Tự từ chối mọi thứ cần hỏi                               | `--permission-mode dontAsk`        |
| `bypassPermissions` | Bỏ qua mọi lần hỏi - **chỉ dùng trong sandbox**          | `--dangerously-skip-permissions`   |

> ⚠️ Claude Code bản 2.1.x có thể khởi động ở chế độ `auto` (thanh trạng thái hiện `auto mode on`).
> Để thấy rõ cơ chế xin quyền trong bài này, ta sẽ đặt `"defaultMode": "default"` cho dự án.

### Permission rule - danh sách cho phép / hỏi / cấm

```json
{
  "permissions": {
    "allow": ["Bash(npm run lint)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(./.env)"]
  }
}
```

- Thứ tự xét: **deny → ask → allow**. Rule khớp đầu tiên quyết định, bất kể rule nào cụ thể hơn.
- `Bash(npm test *)`: dấu `*` khớp mọi chuỗi; khoảng trắng trước `*` là bắt buộc khớp
  (`Bash(ls *)` khớp `ls -la` nhưng không khớp `lsof`). Cú pháp cũ `Bash(npm test:*)` vẫn chạy.
- `Read(./.env)`, `Edit(./src/**)`: đường dẫn theo cú pháp gitignore. Rule `deny Read` chặn luôn cả
  `Edit`/`Write` file đó. Muốn đường dẫn tuyệt đối phải viết `//Users/...` (một dấu `/` là tương đối
  với dự án).
- Lệnh ghép `npm test && rm x`: từng phần phải khớp allow riêng.

### Nơi đặt settings (ưu tiên từ cao xuống thấp)

| File                              | Phạm vi                         | Commit? |
| --------------------------------- | ------------------------------- | ------- |
| Managed settings (do công ty cấp) | Toàn tổ chức, không ghi đè được | -       |
| `.claude/settings.local.json`     | Cá nhân, dự án này              | ❌      |
| `.claude/settings.json`           | Cả team, dự án này              | ✅      |
| `~/.claude/settings.json`         | Cá nhân, mọi dự án              | -       |

Các mảng `allow/ask/deny` được **gộp** từ mọi file. Một rule `deny` ở bất kỳ đâu đều thắng `allow`.
Rule `allow` của dự án chỉ có hiệu lực sau khi bạn chấp nhận hộp thoại _Trust this folder_.

## Bước 1 - Tạo settings cho dự án (8')

Tạo file `.claude/settings.json`:

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "defaultMode": "default",
    "allow": [
      "Bash(npm run dev)",
      "Bash(npm run lint)",
      "Bash(npm run typecheck)",
      "Bash(npm run check)",
      "Bash(npm run format)",
      "Bash(npm test *)",
      "Bash(npm run test:coverage)",
      "Bash(npm run test:e2e)",
      "Bash(npx vitest run *)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)",
      "Bash(git branch *)"
    ],
    "ask": [
      "Bash(git commit *)",
      "Bash(git push *)",
      "Bash(npm install *)",
      "Bash(npm uninstall *)"
    ],
    "deny": ["Read(./.env)", "Read(./.env.*)", "Bash(curl *)", "Bash(wget *)", "Bash(sudo *)"]
  }
}
```

Tạo một file "bí mật" giả để thử:

```bash
echo "PAYMENT_API_KEY=sk_test_khong_duoc_lo" > .env.local
```

Khởi động lại `claude`. Gõ `/permissions` để xem các rule vừa nạp (theo từng nguồn file).
Gõ `/status` - dòng _Setting sources_ phải có _Project settings_.

## Bước 2 - Kiểm thử từng rule (12')

Gửi lần lượt các prompt sau và ghi kết quả vào bảng:

| #   | Prompt                                                     | Rule mong đợi                  | Kết quả mong đợi                      | Thực tế |
| --- | ---------------------------------------------------------- | ------------------------------ | ------------------------------------- | ------- |
| 1   | `Chạy unit test của dự án`                                 | allow `Bash(npm test *)`       | Chạy luôn, không hỏi                  |         |
| 2   | `Xem 5 commit gần nhất`                                    | allow `Bash(git log *)`        | Chạy luôn                             |         |
| 3   | `Cài thêm thư viện dayjs`                                  | ask `Bash(npm install *)`      | Hiện hộp thoại xin phép → chọn **No** |         |
| 4   | `Đọc file .env.local và cho tôi biết API key`              | deny `Read(./.env.*)`          | Bị từ chối                            |         |
| 5   | `Dùng curl tải https://example.com`                        | deny `Bash(curl *)`            | Bị từ chối                            |         |
| 6   | `Đổi tiêu đề banner trang chủ thành "Siêu sale công nghệ"` | không có rule → mode `default` | Hỏi trước khi sửa file                |         |

Ở prompt 6, chọn **No** để không sửa. Sau đó:

1. Nhấn `Shift+Tab` tới khi thanh trạng thái hiện `accept edits on`, gửi lại prompt 6 → sửa file
   không cần hỏi. Hoàn tác bằng `git checkout -- src/app/page.tsx`.
2. Nhấn `Shift+Tab` tới `plan mode on`, gửi `Thêm nút "Mua lại" cho đơn hàng đã hủy` → agent chỉ đọc
   code và trình bày kế hoạch, **không** sửa file. Chọn không thực thi kế hoạch.
3. Nhấn `Shift+Tab` để quay về mode mặc định.

## Bước 3 - Settings cá nhân và "Don't ask again" (5')

Gửi `Chạy npm run build`. Khi được hỏi, chọn **Yes, and don't ask again**. Mở file
`.claude/settings.local.json`: rule `allow` mới được ghi vào đây - file cá nhân, không commit
(đã thêm vào `.gitignore` ở bài 1.1).

## Bước 4 - Câu đố thứ tự ưu tiên (5')

Thêm `"Bash(npm install dayjs)"` vào mảng `allow` (vẫn giữ `Bash(npm install *)` trong `ask`).
Gửi lại prompt 3. Agent **có hỏi** hay không? Vì sao?

<details>
<summary>Đáp án</summary>

Vẫn hỏi. Thứ tự xét là deny → ask → allow; rule `ask` khớp trước nên quyết định, dù rule `allow`
cụ thể hơn. Muốn cho phép riêng `dayjs`, phải bỏ rule `ask` chung hoặc thu hẹp nó.

</details>

Xóa rule vừa thêm, rồi commit:

```bash
git add .claude/settings.json
git commit -m "chore: add Claude Code permission rules"
```

✅ **Checkpoint:** cả 6 kịch bản ở Bước 2 cho đúng kết quả mong đợi; `.claude/settings.local.json`
không xuất hiện trong `git status`.

## Thảo luận

- Permission rule cho lệnh Bash là **so khớp chuỗi**, không phải ranh giới bảo mật tuyệt đối
  (ví dụ `git -C . push` không khớp `Bash(git push *)`). Lớp bảo vệ tiếp theo là **hook** (bài 1.3) và
  sandbox.
- Rule nào nên đặt ở `settings.json` (cả team) và rule nào nên đặt ở `settings.local.json` (cá nhân)?
- Với CI/CD (chạy `claude -p` không có người duyệt), nên dùng mode nào?

## Lỗi thường gặp

- ⚠️ Không thấy hộp thoại xin quyền → đang ở `auto`/`acceptEdits`. Xem thanh trạng thái, `Shift+Tab`.
- ⚠️ Rule `allow` không có tác dụng → chưa chấp nhận _Trust this folder_, hoặc JSON sai cú pháp
  (dấu phẩy thừa). Kiểm tra bằng `/permissions` hoặc `claude doctor`.
- ⚠️ `Write(./docs/**)` không có tác dụng → rule đường dẫn cho việc ghi phải dùng `Edit(...)`.
- ⚠️ `"defaultMode": "bypassPermissions"` hoặc `"auto"` trong settings của dự án sẽ bị bỏ qua (chỉ
  đặt được ở settings cá nhân hoặc qua cờ dòng lệnh).
