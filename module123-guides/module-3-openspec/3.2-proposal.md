# 3.2 - Tạo proposal cho tính năng mới

**Thời lượng:** 25 phút · **Kết quả:** change `openspec/changes/add-wishlist/` hợp lệ (`validate --strict`).

Tính năng của module này: **Danh sách yêu thích (wishlist).**

## Bước 1 - `/opsx:propose` (10')

Mở [reference/feature-brief-wishlist.md](reference/feature-brief-wishlist.md). Gõ `/opsx:propose add-wishlist:`
rồi dán khối **Nội dung để dán vào /opsx:propose**.

Agent sẽ chạy các lệnh `openspec` (đã được phép sẵn trong command) để:

1. `openspec new change add-wishlist` - tạo thư mục change.
2. Lần lượt lấy instructions (có kèm project context từ `config.yaml`) và viết 4 artifact:

```text
openspec/changes/add-wishlist/
├── .openspec.yaml
├── proposal.md              # Why / What Changes / Capabilities / Impact (+ Ngoài phạm vi theo rule)
├── specs/wishlist/spec.md   # delta: ## ADDED Requirements
├── design.md                # quyết định kỹ thuật, file tạo mới/sửa
└── tasks.md                 # ## 1. Nhóm  - [ ] 1.1 Task...
```

3. Dừng lại chờ bạn review - propose **không** tự code.

## Bước 2 - Đọc hiểu định dạng spec delta (5')

```markdown
## ADDED Requirements

### Requirement: Toggle sản phẩm yêu thích

The system SHALL cho phép khách thêm hoặc bỏ một sản phẩm khỏi danh sách yêu thích bằng nút trái tim.

#### Scenario: Thêm sản phẩm chưa có

- **WHEN** khách bấm nút trái tim của sản phẩm chưa có trong danh sách
- **THEN** sản phẩm được thêm vào danh sách
- **AND** nút chuyển sang trạng thái đã thích (aria-pressed="true")

#### Scenario: Danh sách đã đủ 50 sản phẩm

- **WHEN** khách thích thêm một sản phẩm khi danh sách đã có 50 sản phẩm
- **THEN** sản phẩm không được thêm và khách nhận thông báo danh sách đã đầy
```

Quy tắc định dạng (validator kiểm tra):

- Mỗi requirement có từ khóa **SHALL** hoặc **MUST**.
- Mỗi requirement có ít nhất một `#### Scenario:` - **đúng 4 dấu `#`**.
- Change sau này sửa hành vi đã có sẽ dùng `## MODIFIED Requirements` (chép lại toàn bộ requirement),
  bỏ hành vi dùng `## REMOVED Requirements` (kèm **Reason** và **Migration**).

## Bước 3 - Review bằng CLI (5')

```bash
openspec list                                  # các change đang mở
openspec status --change add-wishlist          # artifact nào đã xong
openspec show add-wishlist                     # xem nội dung change
openspec validate add-wishlist --strict        # kiểm tra định dạng
openspec view                                  # dashboard tương tác
```

Checklist review nội dung:

- [ ] `proposal.md` có mục _Ngoài phạm vi_ (rule trong `config.yaml` có tác dụng không?).
- [ ] Mỗi gạch đầu dòng trong brief đều thành requirement có scenario, gồm cả trường hợp biên
      (đầy 50, sản phẩm hết hàng, dữ liệu localStorage hỏng).
- [ ] `design.md` liệt kê file theo đúng codemap (`src/features/wishlist/`, `src/app/wishlist/page.tsx`,
      sửa `product-card.tsx`, `header.tsx`...).
- [ ] `tasks.md` mỗi nhóm kết thúc bằng task test; task cuối là `npm run check`.

## Bước 4 - Chỉnh sửa (3')

Nếu cần sửa, có hai cách:

- Sửa tay file markdown, rồi `openspec validate add-wishlist --strict`.
- Nhờ agent giữ các artifact nhất quán với nhau:

```text
/opsx:update add-wishlist Thêm requirement: khi dữ liệu wishlist trong localStorage bị hỏng hoặc chứa id
sản phẩm không còn tồn tại thì bỏ qua phần lỗi, không làm crash trang. Cập nhật specs, design và tasks tương ứng.
```

## Bước 5 - Commit (2')

```bash
git add openspec
git commit -m "docs(openspec): propose add-wishlist"
```

✅ **Checkpoint:** `openspec validate add-wishlist --strict` báo hợp lệ; `openspec status --change add-wishlist`
hiển thị 4/4 artifact.
