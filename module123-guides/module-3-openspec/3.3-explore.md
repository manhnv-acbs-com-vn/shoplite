# 3.3 - Khám phá luồng code với `/opsx:explore`

**Thời lượng:** 25 phút · **Kết quả:** hiểu luồng giỏ hàng, dùng hiểu biết đó để cải thiện design của `add-wishlist`.

## Lý thuyết nhanh

`/opsx:explore` đưa agent vào chế độ **"cùng suy nghĩ"**: đọc code, so sánh phương án, vẽ sơ đồ ASCII.
Nó **không viết code**, và chỉ ghi vào artifact của change khi bạn đồng ý rõ ràng.

Dùng explore khi: tiếp nhận codebase lạ, ý tưởng còn mơ hồ, cần so sánh nhiều hướng thiết kế,
hoặc - như bài này - kiểm tra xem proposal có khớp với code thực tế không.

> 💡 Trong thực tế, explore thường đứng **trước** propose. Ở lab này ta làm sau để thấy rõ explore giúp
> phát hiện chỗ proposal còn thiếu.

## Bài A - Luồng "Thêm vào giỏ" (10')

Wishlist sẽ dùng lại kiến trúc của giỏ hàng, nên hiểu giỏ hàng trước:

**Prompt**

```text
/opsx:explore Giải thích luồng "Thêm vào giỏ" của ShopLite: từ lúc khách bấm nút trên ProductCard tới khi
badge trên header cập nhật và dữ liệu nằm trong localStorage. Vẽ sơ đồ ASCII các bước, ghi rõ file:dòng.
Giải thích vai trò của useSyncExternalStore, getServerSnapshot và cờ hydrated.
```

Kết quả mong đợi (đại ý):

```text
ProductCard ─► AddToCartButton.handleClick ─► useCart().addItem(product)
                                               │  (src/features/cart/use-cart.ts)
                                               ▼
                             cartStore.dispatch({type:"add"})        (cart-store.ts)
                                   │                      │
                       cartReducer(state, action)    writeToStorage → localStorage["shoplite:cart"]
                         (cart-reducer.ts: giới hạn       │
                          10 sp & tồn kho)                ▼
                                                   emit() → mọi component dùng useCart() render lại
                                                          → CartBadge, CartView, CheckoutForm
Tab khác: sự kiện "storage" → handleStorageEvent → đọc lại → emit()
```

Hỏi tiếp để đào sâu (vẫn trong explore):

```text
Nếu mở 2 tab và thêm sản phẩm ở tab 1 thì tab 2 cập nhật thế nào?
Vì sao server render luôn thấy giỏ hàng trống, và điều gì xảy ra nếu bỏ cờ hydrated trong CartBadge?
Giỏ hàng lưu "snapshot" sản phẩm (tên, giá) - ưu và nhược điểm so với chỉ lưu productId?
```

Ghi lại 3 điều bạn học được.

## Bài B - Đối chiếu với proposal `add-wishlist` (10')

**Prompt**

```text
/opsx:explore So sánh design.md và tasks.md của change add-wishlist với luồng giỏ hàng vừa phân tích.
Design có tái sử dụng đúng pattern (hàm thuần + store + useSyncExternalStore + localStorage + đồng bộ tab) không?
Wishlist nên lưu productId hay snapshot như giỏ hàng, vì sao? Có rủi ro nào về hydration, accessibility
(nút trái tim nằm trong thẻ có Link ảnh aria-hidden), hay sản phẩm bị xóa khỏi catalog mà design chưa xử lý?
Liệt kê các điểm cần chỉnh.
```

Khi agent đề nghị cập nhật artifact, đồng ý cho nó ghi (hoặc dùng `/opsx:update`):

```text
/opsx:update add-wishlist Áp dụng các điểm chỉnh vừa thống nhất trong explore vào design.md và tasks.md.
Thêm vào design.md mục "Luồng tham chiếu" chứa sơ đồ ASCII luồng giỏ hàng.
```

```bash
openspec validate add-wishlist --strict
git diff openspec/        # xem explore đã thay đổi gì trong change
git add openspec && git commit -m "docs(openspec): refine add-wishlist design after exploring cart flow"
```
