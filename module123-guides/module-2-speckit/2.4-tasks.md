# 2.4 - Chia task với `/speckit-tasks` và kiểm tra nhất quán với `/speckit-analyze`

**Thời lượng:** 15 phút · **Kết quả:** `tasks.md` đã qua phân tích nhất quán.

## Bước 1 - Sinh tasks (5')

Theo mặc định template của Spec Kit chỉ sinh task test **khi được yêu cầu**. Constitution của ta yêu
cầu test trước, nên nói rõ:

**Prompt**

```text
/speckit-tasks Áp dụng TDD: với mỗi user story, task viết test (unit cho logic, component/route test cho UI và API)
đứng TRƯỚC task cài đặt. Đánh dấu [P] cho task chạy song song được. Task cuối của mỗi phase là chạy npm run check.
Thêm task cập nhật e2e/shopping-flow.spec.ts với một kịch bản dùng mã SHOPLITE10.
```

Cấu trúc `tasks.md`:

```text
## Phase 1: Setup
## Phase 2: Foundational          ← phần dùng chung, chặn mọi user story (ví dụ dữ liệu mã, kiểu dữ liệu)
## Phase 3: User Story 1 (P1) 🎯 MVP
- [ ] T010 [P] [US1] Viết unit test cho ... trong src/features/coupons/...test.ts
- [ ] T011 [US1] Cài đặt ... trong src/features/coupons/...
## Phase 4: User Story 2 (P2)
...
## Phase N: Polish & Cross-Cutting
```

- `T010` - mã task; `[P]` - song song được (khác file, không phụ thuộc); `[US1]` - thuộc user story nào.
- Mỗi task phải có **đường dẫn file cụ thể**.

## Bước 2 - Review tasks (4')

- [ ] Mỗi Functional Requirement (`FR-xxx`) trong spec đều có ít nhất một task.
- [ ] Task test đứng trước task cài đặt tương ứng.
- [ ] Không có task "mơ hồ" kiểu "Hoàn thiện tính năng".
- [ ] Phase 3 (MVP) tự nó đã tạo ra giá trị dùng được: áp dụng mã và thấy giảm giá.

## Bước 3 - `/speckit-analyze` (5')

```text
/speckit-analyze
```

Lệnh này **chỉ đọc**, không sửa file. Nó đối chiếu `spec.md` ↔ `plan.md` ↔ `tasks.md` ↔ constitution và
xuất bảng: `ID | Category | Severity | Location | Summary | Recommendation`. Vi phạm constitution luôn là
**CRITICAL**.

Xử lý kết quả:

- CRITICAL / HIGH: phải sửa trước khi implement. Ví dụ yêu cầu agent:
  `Sửa các vấn đề C1, H2 trong báo cáo analyze: cập nhật tasks.md và plan.md tương ứng.`
- MEDIUM / LOW: quyết định sửa hoặc ghi nhận lý do bỏ qua.

Chạy lại `/speckit-analyze` đến khi không còn CRITICAL.

