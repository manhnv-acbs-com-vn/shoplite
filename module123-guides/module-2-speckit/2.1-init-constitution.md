# 2.1 - Khởi tạo Spec Kit và "luật" của dự án (constitution)

**Thời lượng:** 25 phút · **Kết quả:** Spec Kit được cài vào ShopLite, file `constitution.md` phiên bản 1.0.0.

## Lý thuyết nhanh: Spec-Driven Development (SDD)

Thay vì "nhắn agent rồi sửa tới khi chạy", SDD đặt **spec** làm trung tâm: viết rõ _cái gì / tại sao_
→ lập kế hoạch _làm thế nào_ → chia task → code. Spec là nguồn sự thật, code là sản phẩm sinh ra từ spec.

GitHub **Spec Kit** đóng gói quy trình này thành các lệnh cho agent:

```text
/speckit-constitution → /speckit-specify → (/speckit-clarify) → /speckit-plan → (/speckit-checklist)
      luật dự án           spec tính năng        hỏi làm rõ          kế hoạch kỹ thuật     checklist chất lượng

→ /speckit-tasks → (/speckit-analyze) → /speckit-implement → /speckit-converge
     chia task        kiểm tra nhất quán        code + test           đối chiếu code với spec
```

Lệnh trong ngoặc là tùy chọn nhưng rất nên dùng.

> ⚠️ Spec Kit 1.x đổi cú pháp so với các tutorial năm 2025: `specify init --ai claude` → `--integration claude`;
> `/speckit.specify` (dấu chấm) → `/speckit-specify` (gạch nối, vì giờ là **skill** của Claude Code).

## Bước 1 - Tạo nhánh và cài Spec Kit vào dự án (8')

```bash
cd shoplite
git checkout main && git status        # phải sạch (đã commit Module 1)
git checkout -b lab2-speckit
specify version                        # >= 1.2
specify init --here --integration claude
```

- Thư mục không trống nên CLI hỏi xác nhận gộp → chọn `y`.
- Windows: thêm `--script ps` để dùng script PowerShell (mặc định trên Windows).
- Chạy không tương tác (CI): `specify init --here --integration claude --force --non-interactive`.

Xem những gì vừa được tạo:

```bash
git status
ls .claude/skills            # speckit-constitution, speckit-specify, ... (10 skill)
ls .specify .specify/memory .specify/templates .specify/scripts/*
```

| Thư mục / file                      | Vai trò                                          |
| ----------------------------------- | ------------------------------------------------ |
| `.claude/skills/speckit-*/SKILL.md` | Các lệnh `/speckit-...` cho Claude Code          |
| `.specify/memory/constitution.md`   | Luật dự án (hiện là template có `[PLACEHOLDER]`) |
| `.specify/templates/*.md`           | Khuôn mẫu cho spec, plan, tasks, checklist       |
| `.specify/scripts/bash/*.sh`        | Script tạo thư mục feature, kiểm tra điều kiện   |

> 💡 Spec Kit **không** sửa `CLAUDE.md`, `AGENTS.md` hay `.claude/settings.json` của bạn.
> CLI có gợi ý thêm `.claude/` vào `.gitignore` - **đừng** làm vậy, vì team cần các skill và settings.

Khởi động lại Claude Code để nạp skill mới, gõ `/speckit` và xem danh sách gợi ý.

## Bước 2 - Viết constitution (12')

Constitution là các nguyên tắc **không thương lượng** mà mọi spec, plan và code phải tuân theo.
Với dự án đang có sẵn (brownfield), nguyên tắc phải dựa trên thực tế của codebase - không bịa ra.

**Prompt**

```text
/speckit-constitution Tạo constitution cho ShopLite dựa trên AGENTS.md, README.md và cấu trúc code hiện tại.
Viết bằng tiếng Việt, giữ từ khóa MUST/SHOULD. Gồm 5 nguyên tắc:
1. Kiến trúc theo tính năng: code trong src/features/<feature>/, src/app chỉ là route mỏng.
2. Test trước cho nghiệp vụ (NON-NEGOTIABLE): mọi quy tắc tính tiền/giới hạn/trạng thái có unit test
   viết trước, gồm giá trị biên; npm run check phải pass.
3. Server là nguồn sự thật về tiền: giá, phí ship, giảm giá, tổng tiền do server tính lại; validate input bằng Zod.
4. Đơn giản trước: dùng stack hiện có, không thêm dependency/database nếu plan không giải thích lý do.
5. Trải nghiệm tiếng Việt và dễ tiếp cận: text tiếng Việt, formatCurrency, form có label và lỗi theo từng trường.
Thêm mục Ràng buộc kỹ thuật, Quy trình phát triển (nhánh riêng, không code khi spec còn câu hỏi mở)
và Governance (sửa constitution phải tăng version semver).
```

Agent sẽ điền vào `.specify/memory/constitution.md`, thêm _Sync Impact Report_ (comment HTML ở đầu
file) và gợi ý commit message.

## Bước 3 - Review constitution (5')

Mở file và tự kiểm tra:

- [ ] Không còn `[PLACEHOLDER]` nào (`grep -n "\[" .specify/memory/constitution.md`).
- [ ] Mỗi nguyên tắc **kiểm chứng được** (đọc PR là biết có vi phạm hay không).
- [ ] Có nguyên tắc nào mâu thuẫn với code hiện tại không? (ví dụ yêu cầu database trong khi dự án dùng file JSON)
- [ ] Phiên bản `1.0.0` và ngày ratify đúng.

So sánh với [reference/constitution.example.md](reference/constitution.example.md).

```bash
git add .specify .claude/skills
git commit -m "docs: init Spec Kit and ratify constitution v1.0.0"
```

✅ **Checkpoint:** gõ `/speckit-` thấy đủ skill; `constitution.md` có 5 nguyên tắc, version 1.0.0.
