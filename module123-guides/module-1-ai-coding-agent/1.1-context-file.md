# 1.1 - Tạo context file cho AI Coding Agent

**Thời lượng:** 35 phút · **Kết quả:** `AGENTS.md`, `CLAUDE.md`, `.claude/rules/testing.md` được commit.

## Lý thuyết nhanh

Mỗi phiên làm việc, agent bắt đầu với "trí nhớ trống". **Context file** là tài liệu agent tự đọc
khi khởi động để biết: dự án là gì, chạy lệnh gì, code nằm đâu, quy ước nào phải theo.

| File                                 | Ai đọc                                                  | Phạm vi                                       | Commit?        |
| ------------------------------------ | ------------------------------------------------------- | --------------------------------------------- | -------------- |
| `CLAUDE.md` hoặc `.claude/CLAUDE.md` | Claude Code                                             | Cả dự án                                      | ✅             |
| `CLAUDE.local.md`                    | Claude Code                                             | Cá nhân, dự án này                            | ❌ (gitignore) |
| `~/.claude/CLAUDE.md`                | Claude Code                                             | Mọi dự án trên máy bạn                        | -              |
| `.claude/rules/*.md`                 | Claude Code                                             | Chỉ nạp khi agent đụng tới file khớp `paths:` | ✅             |
| `AGENTS.md`                          | Chuẩn mở: Codex, Cursor, GitHub Copilot, Claude Code... | Cả dự án                                      | ✅             |

Ghi nhớ:

- Claude Code đọc `AGENTS.md` **chỉ khi không có `CLAUDE.md`**. Cách phổ biến cho team dùng nhiều
  công cụ: viết nội dung chính trong `AGENTS.md`, còn `CLAUDE.md` chỉ cần dòng `@AGENTS.md` (import)
  cộng vài ghi chú riêng cho Claude.
- `@đường/dẫn` trong `CLAUDE.md` là cú pháp import (tối đa 4 cấp lồng nhau). Import không được xử lý
  bên trong khối code.
- Context file là **lời khuyên**, không phải luật cứng. Muốn cưỡng chế → dùng permission (bài 1.2)
  hoặc hook (bài 1.3).
- Nên ngắn (dưới ~200 dòng), cụ thể, kiểm chứng được. Đừng chép lại README.

Một context file tốt trả lời được 6 câu hỏi:

1. Dự án là gì, stack nào?
2. Lệnh build / test / lint là gì?
3. **Codemap**: tính năng nào nằm ở thư mục/file nào, luồng dữ liệu chính chạy qua đâu?
4. Quy ước code (đặt tên, cấu trúc, cách xử lý lỗi)?
5. Quy tắc nghiệp vụ không được phá vỡ?
6. Thế nào là "xong" (Definition of Done)? Điều gì bị cấm?

## Bước 1 - Đo "trước khi có context" (5')

```bash
claude
```

Gửi lần lượt 3 câu hỏi dưới đây. Sau mỗi câu, ghi lại: câu trả lời có đúng không, agent đã mở bao
nhiêu file (xem các dòng `Read(...)`, `Search(...)`). Gõ `/clear` trước mỗi câu để xóa ngữ cảnh.

**Prompt**

```text
Đơn hàng có tạm tính 499.000đ chọn giao hàng tiêu chuẩn thì phí ship bao nhiêu? Quy tắc nằm ở file nào?
```

```text
Tôi muốn thêm kiểu sắp xếp "Tên A → Z" cho trang sản phẩm. Cần sửa những file nào?
```

```text
Trước khi commit tôi cần chạy lệnh gì để chắc chắn không làm hỏng dự án?
```

## Bước 2 - Sinh CLAUDE.md tự động bằng `/init` (5')

```text
/init
```

Claude Code quét codebase và tạo `CLAUDE.md`. Mở file và đánh giá theo 6 câu hỏi ở trên:
phần nào có, phần nào thiếu, phần nào sai hoặc chung chung?

## Bước 3 - Cải tiến thành context file "xịn" (10')

Thông thường `/init` thiếu codemap chi tiết, quy tắc nghiệp vụ và Definition of Done. Bổ sung bằng
cách tự sửa hoặc nhờ agent:

**Prompt**

```text
Cải tiến CLAUDE.md theo cấu trúc sau, ngắn gọn (dưới 120 dòng), viết bằng tiếng Việt:
1. Tổng quan (stack, nơi lưu dữ liệu)
2. Lệnh thường dùng (dev, check, test một thư mục, e2e, format)
3. Codemap: bảng "capability -> thư mục -> file quan trọng" cho catalog, cart, checkout, orders, API,
   kèm mô tả 2 luồng chính: luồng thêm vào giỏ hàng và luồng đặt hàng (từ component tới nơi lưu dữ liệu)
4. Quy ước code (feature-based, đặt tên file, Server/Client Component, Zod, xử lý lỗi API, text tiếng Việt)
5. Quy tắc nghiệp vụ không được phá vỡ (giới hạn giỏ hàng, phí ship, giá do server tính, hủy đơn)
6. Testing (vị trí file test, cách test code dùng file hệ thống, repository in-memory)
7. Không được làm
8. Definition of Done
Chỉ ghi điều kiểm chứng được trong code, trích đúng tên hằng số/hàm. Không chép README.
```

Đọc lại kết quả. Đối chiếu với từng file được nhắc tới - **agent cũng có thể viết sai**.

## Bước 4 - Tách AGENTS.md cho mọi công cụ (5')

```bash
mv CLAUDE.md AGENTS.md
```

Tạo `CLAUDE.md` mới với nội dung:

```markdown
@AGENTS.md

## Dành riêng cho Claude Code

- Tính năng chạm nhiều hơn 3 file: dùng plan mode (Shift+Tab) và trình bày kế hoạch trước khi sửa.
- Sau khi sửa code, tự chạy `npm run check`; nếu fail thì sửa đến khi pass rồi mới báo cáo.
```

Đổi dòng tiêu đề đầu tiên của `AGENTS.md` thành `# AGENTS.md - ShopLite` và thêm một câu
"Hướng dẫn cho mọi AI coding agent làm việc trên repo này".

## Bước 5 - Rule theo đường dẫn (5')

Rule chỉ được nạp khi agent đọc/sửa file khớp `paths`, giúp tiết kiệm context. Tạo
`.claude/rules/testing.md`:

```markdown
---
paths:
  - "src/**/*.test.{ts,tsx}"
  - "e2e/**/*.ts"
---

# Quy tắc viết test

- Tên test viết bằng tiếng Việt, mô tả hành vi: `it("miễn phí giao hàng khi đơn đạt ngưỡng")`.
- Mỗi quy tắc nghiệp vụ có ít nhất 1 test cho giá trị biên (dưới / bằng / trên ngưỡng).
- Component test: ưu tiên `getByRole`, `getByLabelText`; `getByTestId` là lựa chọn cuối.
- Không gọi mạng thật: dùng `vi.stubGlobal("fetch", ...)`.
```

## Bước 6 - Kiểm chứng (5')

Thoát (`/exit`) và mở lại `claude` để nạp file mới, rồi:

```text
/context
```

Mục **Memory files** phải liệt kê `CLAUDE.md` và `AGENTS.md`. (`/memory` cho phép mở nhanh các file này.)

Lặp lại 3 câu hỏi ở Bước 1 (nhớ `/clear` giữa các câu). So sánh:

| Câu hỏi               | Trước: đúng? / số file đã đọc | Sau: đúng? / số file đã đọc |
| --------------------- | ----------------------------- | --------------------------- |
| Phí ship 499.000đ     |                               |                             |
| Sắp xếp A → Z         |                               |                             |
| Lệnh trước khi commit |                               |                             |

Kiểm tra rule theo đường dẫn: yêu cầu agent _"Đọc file src/features/checkout/pricing.test.ts và cho
biết quy tắc viết test của dự án"_ - câu trả lời phải nhắc tới các quy tắc trong `testing.md`.

## Bước 7 - Commit

Thêm các file cá nhân vào `.gitignore` (dùng ở bài sau):

```bash
# macOS / Linux / Git Bash (Windows: mở .gitignore và thêm 3 dòng này bằng tay)
printf '\n# AI agent - local files\nCLAUDE.local.md\n.claude/settings.local.json\n.claude/logs/\n' >> .gitignore
git add AGENTS.md CLAUDE.md .claude/rules .gitignore
git commit -m "docs: add AI agent context files"
```

✅ **Checkpoint:** `/context` hiện cả hai file; agent trả lời đúng 3 câu hỏi mà không cần lục tìm nhiều file.

## Bài tập thêm (nếu còn thời gian)

1. Nhờ agent thực hiện _"Thêm kiểu sắp xếp Tên A → Z cho trang sản phẩm, có test"_. Quan sát agent có
   tự đặt code đúng chỗ, viết test tiếng Việt và chạy `npm run check` như context file yêu cầu không.
2. Viết thêm `.claude/rules/api-routes.md` áp dụng cho `src/app/api/**/*.ts`.
3. Mở `AGENTS.md` bằng một công cụ khác (Cursor, Copilot, Codex) và hỏi cùng câu hỏi.
4. Next.js 16 mới hơn dữ liệu huấn luyện của nhiều model. Gói `next` có kèm tài liệu đúng phiên bản ở
   `node_modules/next/dist/docs/`. Thêm vào `AGENTS.md` một dòng hướng agent đọc tài liệu này trước khi
   dùng API chưa chắc chắn, rồi hỏi agent: _"Trong Next.js 16, params của page có kiểu gì?"_ trước và sau
   khi thêm. (Next.js 16.4 có thể tự chèn một khối hướng dẫn vào `AGENTS.md` khi `next dev` được chạy bởi
   AI agent; ShopLite tắt việc này bằng `agentRules: false` trong `next.config.ts` để repo sạch.)

## Lỗi thường gặp

- ⚠️ Context file quá dài hoặc chép nguyên README → tốn context, agent bỏ sót ý quan trọng.
- ⚠️ Viết chung chung ("viết code sạch", "test đầy đủ") → không kiểm chứng được, agent bỏ qua.
- ⚠️ Viết sai tên file/hàm → agent tin theo và làm sai. Luôn đối chiếu với code.
- ⚠️ Có cả `CLAUDE.md` và `AGENTS.md` nhưng không import → Claude Code bỏ qua `AGENTS.md`.
